# 정산 프로모션 결정사항

## 수동 등록 방식

프로모션은 분기마다 이름, 적용 기간, 단가, 달성 조건이 달라진다. 또한 포스 앱 설치처럼 현재 데이터베이스에 대응하는 이벤트나 테이블이 없는 캠페인도 있으므로, DB 데이터를 기준으로 자동 계산하지 않고 담당자가 프로모션별 이름·기간·단가·달성 건수를 직접 등록하는 방식을 선택했다.

## 테이블과 권한 경계

`settlement_promotions`는 프로모션 이름, 적용 기간, 건당 단가, 수동 입력 달성 건수, 메모와 생성·수정 시각을 저장한다. 금액은 저장하지 않고 조회 시 `unit_rate * achieved_count`로 계산해 단가나 건수를 수정해도 금액이 일관되게 유지되도록 했다.

RLS는 기존 정산 관련 테이블과 같은 방식으로 인증된 사용자의 조회·등록·수정·삭제를 허용한다. 실제 쓰기 권한은 프로필 역할을 확인하는 서버 액션에서 `admin`·`master`·`cs`로 제한한다. 이렇게 하면 모든 로그인 사용자는 공통 대시보드에서 정산 결과를 조회할 수 있고, 입력 변경은 담당 역할만 수행할 수 있다.

## 개발 DB 검증 상태

마이그레이션 파일은 dev Supabase SQL Editor에 수동 적용할 수 있는 형태로 작성했다. 현재 작업 세션에는 dev 프로젝트 접속 정보와 SQL 실행 도구가 없어 실제 적용·등록·기간 필터 검증은 수행하지 않았으며, 운영 DB에는 접근하지 않았다.
