# 택배 발송 체크리스트와 재고 연동 (2026-09-09)

택배 발송 업무 개선안(POSMOS 체크리스트.pptx)을 구현한 기록.

## 왜

완료 시 재고 차감은 접수 때 고른 장비 목록(installations.items)을 그대로 썼다. 택배 건은 실제 보낸
장비가 접수와 다른 일이 잦고, 목록이 비면 아무것도 안 빠졌다. 부족해도 그냥 깎였고, 이력에는 왜 빠졌는지
유형이 없어 실사 차이를 역추적하기 어려웠다.

## 흐름

접수 → 제품준비(체크리스트) → 재고확인 → 택배발송 → 완료(차감·비고 기록) → 재고 실사/이력 검색

- 택배 건에서 상태를 "제품준비"로 바꾸면 체크리스트 팝업이 먼저 뜬다. 접수 장비가 기본값이고
  이름·수량을 고치고 추가할 수 있다. 수량이 있는 항목은 전부 체크해야 저장된다.
- 저장(`saveDeliveryChecklist`)할 때 재고 품목명이 같은 항목의 가용 재고와 비교해 부족하면 저장을 막는다.
  재고에 없는 이름은 저장은 되지만 "차감되지 않는다"고 경고한다(품목명 불일치는 차감 RPC와 같은 규칙).
- 저장하면 `installations.delivery_checklist`(147)에 남기고 `installations.items`도 확정 수량으로 덮어쓴다.
  완료 시 차감이 items를 쓰므로 "택배 완료 수량 = 재고 출고 수량"이 된다.
- 완료(최종 승인·강제완료)하면 기존 차감 RPC가 돌고, 이력에 `log_type`(택배출고/설치출고)이 붙는다.
  택배 건은 비고에 "택배처리 : 토스프론트1 + 영수증프린터1" 한 줄이 자동으로 붙는다(중복 방지).
- 재고 실사 화면의 이력에 유형 배지·유형/품목/상호/기간 필터가 생기고, 설치건이 연결된 이력은 그 건으로 이동한다.
- 매장별 누적 출고이력은 가맹점 360의 "장비 입출고" 카드가 이미 inventory_logs.merchant_id로 보여준다.

## 마이그레이션 전

147이 안 돌았으면 체크리스트 저장은 안내 문구로 막히고, 차감 RPC는 예전 인자로 다시 불러 동작한다.

## 안 한 것

- 택배 목록에서 상호 클릭 시 매장 상세 열기 (별도 작업)
- 재고 수정 시 수정 전/후 값 보존은 기존 이력(change)으로 갈음
