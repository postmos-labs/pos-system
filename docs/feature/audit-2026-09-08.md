# 전산 전체 점검 (2026-09-08)

코드베이스 전체를 세 영역(인입내역·가맹점·챗봇 / 가맹접수·승인·설치·인터넷 / API·인증·공용)으로
나눠 동작 버그와 권한 구멍을 찾았다. 타입 검사와 포맷은 깨끗했고, 린트 114건은 대부분 `any`와
React 훅 규칙이라 손대지 않았다. 아래는 사용자가 항목별로 진행 여부를 정한 결과다.

## 보류한 것 (사용자 결정)

- **이름 로그인.** `/api/auth/login`이 이름만 받고 계정 이메일을 돌려준다. 비밀번호는 다음 단계의
  Supabase 로그인에서 검사되므로 로그인 자체는 뚫리지 않지만 직원 이름과 이메일 열거가 된다.
  현재 방식을 유지하기로 했다.
- **가맹접수 알림톡 API 권한.** `/api/franchise/notify`가 로그인만 확인하고 수신번호를 요청 본문에서
  받는다. 내부 직원만 쓰므로 그대로 두기로 했다.

## 문제없이 확인된 것

- 이관 승인 권한(`approval_role`)과 설치 승인 직급은 화면 조건과 서버 가드가 일치한다. 7번이 유일한 예외였다.
- 관리자 키(`service_role`)를 쓰는 서버 액션은 4번을 빼고 전부 앞단에 권한 가드가 있다. 클라이언트에서 관리자 키를 가져오는 곳은 없다.
- 비로그인 진입점(서명·설치현황·장비선택)의 토큰은 `gen_random_uuid()`라 추측 불가하고 만료·중복 검사가 된다.
- 상태값은 타입 정의와 DB CHECK가 맞는다. `info_input` 하나만 어긋나는데 세 화면 모두 선택지에서 빠져 있다.
- 날짜는 KST 보정이 정확하다. 오늘 넣은 기능들은 마이그레이션 전에도 빈 값으로 뜬다.
