# 통화기록창 재상담 · 재상담/취소 알림 (2026-10-01)

가맹접수 통화기록창(`FranchiseCallDrawer`)에 **재상담** 버튼을 넣고, 재상담·취소가 생기면 미리 정해 둔 사람에게 팝업 알림을 보낸다.

## 재상담

- 버튼 줄은 통화 부재 · 통화완료 · **재상담** · 취소처리 순서.
- 재상담을 누르면 비고 입력칸이 열린다. 위 통화 메모에 써 둔 내용이 있으면 이어받는다. **비고는 필수** — 알림을 받는 사람이 무엇을 다시 상담해야 하는지 알아야 하기 때문.
- 등록하면 세 군데에 남는다.
  - 통화이력: `franchise_application_call_logs`에 `call_type = 'reconsult'`로 (비고는 `note`)
  - 비고 메모: `[이름 날짜] 재상담: …` 스탬프로 덧붙임 — 취소 사유를 남기는 방식과 같다. 목록의 비고 칸에서 바로 보이게 하려는 것
  - 알림: 설정된 사람에게 `franchise_reconsult` 팝업
- 부재/완료 횟수와 "최근 통화" 표시는 건드리지 않는다. 목록의 최근 통화는 부재·완료만 보도록 이미 걸러져 있다(`fetchFranchiseListData`).
- 취소된 접수에는 등록할 수 없다(화면 버튼 비활성 + 서버에서도 거절).

## 알림 받을 사람 설정

- 통화기록창 상단 톱니 버튼 → 재상담 알림 / 취소 알림 탭.
- 탭마다 고를 수 있는 것: 특정 직원(체크), **이 건의 담당 영업**, **이 건의 담당 CS**. 담당자 옵션은 건마다 받는 사람이 달라지는 경우(재상담은 보통 담당자에게 돌아감)를 위해 넣었다.
- 설정은 전사 공용 하나다(`franchise_call_alert_settings`, 이벤트당 한 행). 사람마다 따로 두지 않는다 — "누가 받는지"는 조직이 정하는 것이라서.
- 변경 권한: 관리자·마스터, CS책임·팀장. 나머지는 보기만 한다. 화면의 편집 가능 여부와 저장 서버 액션 가드가 `canEditFranchiseCallAlerts` 하나를 같이 쓴다.
- 처리한 본인은 받지 않는다. 계정이 지워진 사람이 설정에 남아 있으면 그 사람만 빼고 보낸다(알림 FK 위반으로 전체가 실패하지 않게).
- 재상담 등록·취소 확인 창에 "알림: 누구, 누구"로 받을 사람을 미리 보여준다.

## 취소 알림이 가는 경로

- 통화기록창의 **취소처리** 버튼
- 통화기록창에서 **부재 3회로 자동 취소**될 때 (사유 미입력이면 "통화 부재 3회 자동 취소")

상태 드롭다운·일괄 변경·이관 화면에서 취소로 바꾸는 경로는 알림을 보내지 않는다. 요청이 통화기록창 기준이었고, 그 경로들은 사유 입력이 없어 "상태만 변경"으로 설계돼 있다. 넓히려면 `FranchiseClient.updateStatus`에서 `canceled`일 때 `notifyFranchiseCanceled`를 부르면 된다.

## DB (`supabase/157_franchise_call_reconsult_alerts.sql`)

- `franchise_application_call_logs.call_type` CHECK에 `reconsult` 추가
- `franchise_call_alert_settings` 표 신설. RLS는 조회만 열고, 저장은 서버 액션이 권한 검사 후 service_role로 한다.

마이그레이션 적용 전 동작:

- 알림 설정 창: "설정 표가 아직 없습니다" 안내, 편집 불가
- 재상담 등록: "157 마이그레이션을 먼저 실행해주세요" 오류(CHECK 위반)
- 취소처리: 평소대로 취소되고 알림만 안 간다
