# 가맹점 리서치 설문

가맹점 사장님께 정수기·배민·테이블오더·키오스크 관심 여부를 알림톡으로 묻고, 응답한 가맹점을 영업 연락 명단으로 모은다.

## 결정 사항

- **설문 단독 알림톡.** 가맹 접수 완료 알림과 합치지 않는다. 접수 안내와 섞이면 광고성으로 보여 접수 안내까지 묻힌다.
- **수동 발송.** 가맹접수 상세의 "리서치 발송" 버튼으로 담당자가 골라서 보낸다. 자동 발송은 원치 않는 건에도 나가므로 쓰지 않는다.
- **버튼 하나 → 설문 페이지에서 중복 선택.** 처음엔 항목별 버튼 4개를 검토했지만, 카카오 버튼 이름 14자 제한 때문에 원문 문구가 잘리고 검수 부담도 커서 버튼 하나로 바꿨다. 항목 선택(중복 가능)은 웹 페이지에서 한다. 페이지는 `?item=<항목키>`가 오면 그 항목을 미리 체크하는 기능을 남겨 두었지만(`entry_item` 칸), 지금 템플릿은 쓰지 않는다.
- **텔레그램 공지 형식.** 단체방에 영업 연락에 필요한 것만 보낸다: 가맹점명 / 번호 / 관심상품(공백 구분, 항목 정의 순서).
- **가맹점당 링크 하나, 한 번만 제출.** 재발송은 같은 토큰으로 기한(7일)만 늘린다. 제출한 뒤에는 재발송 버튼을 숨긴다.
- **결과 위치.** 가맹접수 상세의 "리서치 설문" 칸, CS 업무 > "리서치 응답" 목록(단계 탭·항목 필터·연락완료 처리), 텔레그램 단체방 알림(제출 즉시).
- **텔레그램은 실패해도 제출은 성공.** 환경변수가 없거나 텔레그램이 응답하지 않으면 로그만 남긴다.

## 흐름

```
가맹접수 상세 "리서치 발송"
  → franchise_surveys 행 생성(토큰) → 알림톡 발송 → sent_at·expires_at 기록
고객이 버튼 클릭 → /survey/<token>
  → 처음 열람이면 opened_at 기록
  → 항목 선택 후 제출 → POST /api/survey → picks·submitted_at 기록 → 텔레그램 알림
리서치 응답 목록에서 연락 후 "연락완료"
```

## 켜기 전에 할 일

1. Supabase SQL Editor에서 `157_franchise_surveys.sql` 실행
2. 솔라피 알림톡 템플릿 "가맹점 오픈준비 리서치" 검수 통과 후 Vercel 환경변수 `SOLAPI_KAKAO_TEMPLATE_FRANCHISE_SURVEY`에 템플릿 ID
   - 처음 올린 정보형·혜택형 두 템플릿은 모두 반려됐다(2026-10-26). 사유: "수신자가 요청하지 않은 내용으로 광고성 및 공지성 메시지". 문구가 아니라 발송 목적이 문제라 본문에 후킹 문구를 빼도 같은 사유로 막혔다
   - 그래서 **상담 중 고객이 안내를 요청한 경우에만 보내는 정보성 안내**로 바꿔 재검수 요청(2026-10-27). 강조 제목 `요청하신 오픈 준비 안내`, 보조문구 `가맹 상담 요청 고객 안내`, 버튼 `안내 항목 선택하기` → `https://#{링크}`
   - 본문에는 가격·할인 문구를 넣지 않는다. 후킹 문구는 설문 페이지(`src/lib/survey.ts`)에만 둔다
   - 발송 버튼은 "고객이 직접 요청했나요?" 확인을 거친다. 요청하지 않은 고객에게 보내면 템플릿 문구가 거짓이 되고 채널 제재 위험이 있다
   - 브랜드메시지(광고)는 마케팅 수신 동의가 필요해 지금은 쓰지 않는다. 카카오 채널 친구에게는 동의 없이 보낼 수 있다
   - 템플릿 본문을 고치면 `src/lib/solapi.ts` `sendFranchiseSurvey`의 text도 똑같이 고쳐야 한다(다르면 발송 실패)
3. 텔레그램: BotFather로 봇 생성 → 단체방에 초대 → Vercel 환경변수 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_SURVEY_CHAT_ID`(방 chat id, 보통 `-100`으로 시작)

템플릿 환경변수가 없으면 발송 버튼은 안내 메시지만 띄우고 아무것도 보내지 않는다.
